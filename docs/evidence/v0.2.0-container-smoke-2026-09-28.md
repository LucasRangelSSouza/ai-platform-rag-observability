# v0.2.0 container smoke record

**Date:** 2026-09-28  
**Environment:** Windows 11, Docker Engine 26.1.1

## Scope

This record verifies the repository's fixture Compose profile as a real container run. It does not claim a provider-backed generation run, a live gateway integration, or a Langfuse ingestion run.

## Commands

```powershell
docker compose --profile fixture up -d --build --wait
Invoke-RestMethod http://127.0.0.1:8080/healthz
Invoke-RestMethod -Method Post http://127.0.0.1:8080/v1/answer `
  -ContentType application/json `
  -Body '{"question":"How does the retrieval service abstain?"}'
docker compose --profile fixture down
```

## Observed result

The image built as `rag-platform:0.2.0` with image ID prefix `6961730e2e5e`. Compose reported the `rag-fixture` service healthy. The health endpoint returned:

```json
{"status":"ok","documents":6,"retrieval":"bm25","generator":"extractive"}
```

The answer endpoint returned `status: "answered"` and cited `safety#c000`. Its answer explained that the service abstains when the approved corpus lacks evidence and rejects prompt-injection patterns. The response did not contain an input question, and the trace used an opaque identifier.

The service was published only on `127.0.0.1:8080` during the check. The Compose definition uses a read-only root filesystem, a temporary `/tmp`, dropped Linux capabilities, `no-new-privileges`, and an unprivileged runtime user.
