# v0.2.0 Langfuse local integration record

**Date:** 2026-09-28  
**Environment:** Windows 11, Docker Engine 26.1.1, Langfuse fork commit `7ad9dfed444102f4ae678b7661d5c4ba9f934428`

## Scope

This is a local, disposable integration run. The Langfuse stack ran with test-only credentials and a test-only project; it was not exposed as a hosted service and no provider account was involved.

## Result

The Langfuse web, worker, PostgreSQL, Redis, ClickHouse, and object-storage services all reached their Compose health checks. The RAG CLI then answered the synthetic fixture question below while exporting its trace to the self-hosted Langfuse ingestion endpoint:

```powershell
python -m rag_platform answer `
  --question "How does the retrieval service abstain?" `
  --trace-export langfuse
```

The answer returned `status: "answered"` with citation `safety#c000`. A subsequent authenticated query to the local Langfuse public API returned the exported trace. Its stored representation had `input: null` and `output: null`; the metadata contained the result state, citation count, safety state, and a SHA-256 question digest. The trace had two observations and two scores.

## Compatibility finding

The current fork runs Langfuse v4. The RAG client uses the legacy `POST /api/public/ingestion` batch contract. In the v4 default `events_only` mode, Langfuse correctly rejected those legacy events. The integration therefore used the documented `LANGFUSE_MIGRATION_V4_WRITE_MODE=dual` setting on both web and worker services. With dual write enabled, Langfuse accepted all five redacted ingestion events in the batch.

This bridge proves the existing client's behaviour against a running Langfuse service. It is not a permanent compatibility claim. A future RAG release should use a native v4 event or OTLP ingestion path and then repeat this run without the migration bridge.

## Privacy checks

The stored trace did not contain the fixture question, retrieved passage text, or generated answer text. The repository's exporter omits those fields unless `--trace-include-content` is explicitly supplied. The local test stack and its volumes were removed after validation.
